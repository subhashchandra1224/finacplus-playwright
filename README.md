## Configuration

All credentials are supplied via environment variables. Never commit real values.

### Required environment variables

| Variable           | Description |
|--------------------|-------------|
| `DEMOQA_USERNAME`  | Your DemoQA account username (created manually at demoqa.com/register) |
| `DEMOQA_PASSWORD`  | Your DemoQA account password |
| `REQRES_PROJECT_KEY` | ReqRes environment-scoped project key (`pro_*` prefix) — see below |
| `REQRES_COLLECTION` | Collection slug to use (default: `products`) |

### Getting the ReqRes project key

The persistent Create → GET → Update workflow requires a **project key**, not the
free-tier demo key (`free_user_*`). The demo key only works with the legacy
`/api/users` endpoint which does not persist records.

Steps:
1. Go to **https://app.reqres.in/api-keys**
2. Copy or create a **manage key** (prefix: `pro_*`)
3. Set it as `REQRES_PROJECT_KEY=pro_xxxx`

The starter project on reqres.in includes a `products` collection by default.
Set `REQRES_COLLECTION=products` or create a custom collection at
https://app.reqres.in/collections.

### Setting up credentials

Create a `.env` file (git-ignored):
```
DEMOQA_USERNAME=your_demoqa_username
DEMOQA_PASSWORD=your_demoqa_password
REQRES_PROJECT_KEY=pro_your_project_key
REQRES_COLLECTION=products
```

Then set the variables in your shell before running:

**Windows PowerShell:**
```powershell
$env:DEMOQA_USERNAME="your_username"
$env:DEMOQA_PASSWORD="your_password"
$env:REQRES_PROJECT_KEY="pro_your_key"
$env:REQRES_COLLECTION="products"
npx playwright test
```

**Mac/Linux:**
```bash
DEMOQA_USERNAME=your_username \
DEMOQA_PASSWORD=your_password \
REQRES_PROJECT_KEY=pro_your_key \
REQRES_COLLECTION=products \
npx playwright test
```

## API Tests — reqres.spec.js (3 tests)

Uses the **ReqRes Persistent Collections API** (`/api/collections/{slug}/records`).
Records created via POST are genuinely persisted and retrievable via GET.

| Test | Endpoint | What is validated |
|------|----------|-------------------|
| POST — create record | `POST /api/collections/{slug}/records` | Status 201, `name` and `job` match payload, dynamic `id` stored |
| GET created user | `GET /api/collections/{slug}/records/{id}` | Status 200, `id` matches POST id, `name` = "FinacPlus QA", `job` = "Automation Engineer" |
| PUT — update name | `PUT /api/collections/{slug}/records/{id}` | Status 200, `name` = "FinacPlus QA Updated", `job` = "Senior Automation Engineer" |

All three tests use the same dynamic ID returned by POST. No hardcoded IDs.
A cleanup step deletes the created record after tests complete.

### API endpoint used

```
Base: https://reqres.in
POST   /api/collections/{slug}/records
GET    /api/collections/{slug}/records/{id}
PUT    /api/collections/{slug}/records/{id}
DELETE /api/collections/{slug}/records/{id}   (cleanup)

Headers required:
  x-api-key: <REQRES_PROJECT_KEY>
  Content-Type: application/json

Body format:
  { "data": { "name": "...", "job": "..." } }
```

### Note on collection name

The reqres.in starter project includes a `products` collection by default.
The assignment requires storing `name` and `job` fields — these are stored inside
the collection record's `data` field regardless of the collection name.
The collection acts as the persistence layer; the field names satisfy the assignment requirement.
