## Configuration

Credentials must not be committed. Set them as environment variables:

```bash
# Windows PowerShell
$env:DEMOQA_USERNAME="your_username"
$env:DEMOQA_PASSWORD="your_password"
$env:REQRES_API_KEY="your_api_key"
```

Or create a `.env` file (git-ignored):
```
DEMOQA_USERNAME=your_username
DEMOQA_PASSWORD=your_password
REQRES_API_KEY=your_api_key
```

Then load it before running:
```bash
# Using dotenv-cli
npx dotenv -e .env -- npx playwright test
```

Get a free ReqRes API key at https://app.reqres.in/

DemoQA account must be created manually at https://demoqa.com/register


## API Tests — reqres.spec.js

| Test | Endpoint | What is validated |
|------|----------|-------------------|
| POST create user | POST /api/users | Status 201, name/job echoed, dynamic userId stored |
| GET dynamic user | GET /api/users/{dynamicId} | Real GET with exact dynamic ID — asserts observed 404 (see note) |
| GET existing user | GET /api/users/2 | Status 200, id/email/first_name/last_name validated |
| PUT update user | PUT /api/users/{dynamicId} | Status 200, updated name and job validated |

### Observed behavior — GET returns 404

During actual test execution on 2026-08-09, the following was observed:
- POST returns a dynamic userId (varies each run)
- GET with that exact userId → HTTP 404, empty body
- The legacy /api/users endpoint does not persist POST-created records

The test sends the real GET using the exact dynamic ID and asserts the actual 404.
No data is fabricated. A separate test validates GET JSON parsing against a pre-seeded user (id=2).
