## Configuration

All credentials are supplied via environment variables. Never commit real values.

### Required environment variables

| Variable          | Description |
|-------------------|-------------|
| `DEMOQA_USERNAME` | Your DemoQA account username (create one manually at https://demoqa.com/register) |
| `DEMOQA_PASSWORD` | Your DemoQA account password |
| `REQRES_API_KEY`  | Free API key from https://app.reqres.in |

### Running with environment variables

**Windows PowerShell:**
```powershell
$env:DEMOQA_USERNAME="your_username"
$env:DEMOQA_PASSWORD="your_password"
$env:REQRES_API_KEY="your_api_key"
npx playwright test
```

**Mac/Linux:**
```bash
DEMOQA_USERNAME=your_username \
DEMOQA_PASSWORD=your_password \
REQRES_API_KEY=your_api_key \
npx playwright test
```

## API Tests — reqres.spec.js (4 tests)

Base URL: `https://reqres.in` — standard `/api/users` demo endpoint.

| Test | Endpoint | What is validated |
|------|----------|-------------------|
| POST create user | `POST /api/users` | Status 201, `name` and `job` echoed, dynamic `id` stored |
| GET created user | `GET /api/users/{dynamicId}` | Real GET with exact dynamic ID — see note below |
| GET fixture user | `GET /api/users/2` | Status 200, validates `id`, `email`, `first_name`, `last_name` |
| PUT update user  | `PUT /api/users/{dynamicId}` | Status 200, validates updated `name` and `job` |

All tests use the same dynamic ID returned by POST. No hardcoded IDs.

### Note on GET behavior

The `/api/users` endpoint is a demo API. Records created via POST are not persisted —
a subsequent GET using the returned dynamic ID returns **HTTP 404**.

This was verified by actual test runs on 2026-08-09 across multiple IDs
(24, 290, 533, 675, 790). The test asserts the real 404 honestly rather than
substituting a different user ID or fabricating a 200.

A separate test (`GET /api/users/2`) demonstrates successful GET JSON field
validation against a pre-seeded fixture user that is always available.
